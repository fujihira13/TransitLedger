# TransitLedger 現行仕様整理（As-Is）

> **目的**: 既存WebアプリをもとにAndroid/iOS向けアプリを一から作り直すための要件定義の土台。
> **方針**: 実装・コードから読み取れる「現在の仕様」を整理する。実装方針・改善提案は含まない。
> **注記**: `traffic-expenses-requirements.md`（MVP要件定義書）との差異も末尾に記載する。

---

# 1. アプリ概要

**アプリ名**: TransitLedger
**表示名（ヘッダー）**: 交通費・交際費かんたん記録

交通費と交際費を手軽に記録・集計・管理するためのローカルファーストPWA。
サーバーなし・認証なし・全データをブラウザの `localStorage` に保存する完全オフライン動作アプリ。
モバイルブラウザからのホーム画面追加（PWAインストール）に対応し、スマートフォンでの利用を主眼に置いたUI設計。

---

# 2. 主な利用者

- **推定**: 個人ユーザー（交通費・交際費の自己管理が必要な人）
- ユーザー登録・ログインは存在しない → シングルユーザー前提
- 端末に紐づくデータ管理（複数端末間の同期機能はない）
- 日本語専用（UI全体が日本語）

# 4. 画面一覧

## 4.1 画面構成

全画面共通レイアウト：固定ヘッダー + スクロールコンテンツ + 固定フッターナビゲーション
フッターに4タブが常に表示され、タブで画面を切り替える。

| パス | 画面名 | 役割 |
|------|--------|------|
| `/add` | 支出追加画面 | 新規支出レコードの入力・登録 |
| `/list` | 支出一覧画面 | 登録済み支出の表示・編集・削除 |
| `/summary` | 集計・分析画面 | 期間別の統計・インサイト閲覧 |
| `/settings` | 設定画面 | テンプレート管理・エクスポート・インポート・全削除 |
| `/` | （リダイレクト） | 自動で `/add` に転送 |

## 4.2 画面遷移

```
起動 → /add（デフォルト）
/add で保存成功 → /list に自動遷移
/list で支出タップ → 編集モーダル（ページ遷移なし）
フッターナビゲーション → 任意の画面へ遷移
/settings で復元・全削除 → window.location.reload() でアプリ再起動
```

## 4.3 各画面の詳細

### 支出追加画面（/add）

**主な表示要素:**
- テンプレートチップ（登録済みテンプレートの一覧）
- 頻出金額チップ（直近90日の上位5件、金額フィールドにフォーカスで表示）
- 入力フォーム: 日付 / 金額 / 区分 / サブ区分 / メモ / 満足度
- 保存ボタン

**主な操作:**
- テンプレートチップをタップ → 金額・メモが自動補完
- 金額フィールドにフォーカス → 頻出金額チップが表示される
- 区分を変更 → サブ区分が自動リセット
- メモ入力中 → 残り文字数をリアルタイム表示（残り20文字未満で赤色）
- 保存成功後 → 一覧画面へ自動遷移

### 支出一覧画面（/list）

**主な表示要素:**
- フィルタバー: 今月 / 先月 / 全て / 月指定（カスタム）、区分選択
- 支出リスト（日付降順 → 同一日は登録日時降順）
- 各支出アイテム: 日付・区分・サブ区分・金額・メモ（最大2行）・満足度ラベル・削除ボタン
- 編集モーダル（支出タップで表示）
- 削除確認ダイアログ

**フィルタ種別:**

| フィルタ | 選択肢 |
|--------|--------|
| 月フィルタ | 今月 / 先月 / 全て / カスタム月指定（YYYY-MM） |
| 区分フィルタ | 全て / 交通費 / 交際費 |

### 集計・分析画面（/summary）

**主な表示要素:**
- 期間指定（開始日〜終了日、デフォルト: 今月）
- 区分別合計（交通費・交際費・総合計）
- サブ区分内訳（金額・割合%）
- 満足度統計（平均・1〜5段階の分布）
- インサイト（タクシー比率・交際費TOP3日・週次平均比較）

**集計ロジック:**
- 期間変更 → すべての集計値が即座に再計算（useMemoで最適化）
- 週次比較は月曜日始まりで算出（設定値: `week_start: 1`）

### 設定画面（/settings）

**セクション構成:**

| # | セクション | 内容 |
|---|----------|------|
| 1 | テンプレート管理 | 一覧表示・作成・編集・削除・並び替え |
| 2 | データ保存についての注意書き | localStorageの制約説明（消失リスク） |
| 3 | CSVエクスポート | 期間指定してCSVダウンロード |
| 4 | JSONバックアップ | 全データをJSONでダウンロード |
| 5 | データ復元 | JSONファイルを選択してインポート |
| 6 | 危険な操作 | 全データ削除ボタン（赤色、確認必須） |

## 6.1 支出入力フォーム

| 項目 | ルール | エラーメッセージ |
|------|--------|----------------|
| 日付 | 必須、YYYY-MM-DD形式（正規表現チェック） | "日付はYYYY-MM-DD形式で入力してください" |
| 金額 | 必須、1以上の数値 | "金額は1以上である必要があります" |
| 区分 | 必須 | （表示エラーのみ、テキストメッセージ未確認） |

| 満足度 | 任意、1〜5の整数またはnull | "満足度は1〜5の範囲で入力してください" |

**補足:**
- 金額は `inputMode="numeric"` で数値キーボードを優先表示
- `min="1"`, `step="1"` 属性で負数・小数の入力を制御
- メモは残り文字数をリアルタイム表示（残り20文字未満で赤色警告）

## 6.2 テンプレートフォーム

| 項目 | ルール | エラーメッセージ |
|------|--------|----------------|
| テンプレート名 | 必須、トリム後に空白不可 | "表示名は必須です" |
| 区分 | 必須 | - |
| サブ区分 | 必須（区分に対して有効な値） | - |
| 金額 | 任意、設定する場合は1以上 | "金額は1以上である必要があります" |
| メモ雛形 | 任意 | - |

## 6.3 バックアップインポート

| 確認項目 | ルール |
|--------|--------|
| ファイル形式 | `.json` のみ受け付け（input[accept=".json"]） |
| データ構造 | schemaVersion / exportedAt / expenses[] / templates[] / settings の存在確認 |
| スキーマバージョン | 現在の設定（`schema_version: 1`）と一致必須 |
| 不一致時 | `SCHEMA_MISMATCH` エラーでインポート拒否 |

# 7. 業務ルール

| # | ルール | 根拠 |
|---|--------|------|
| 1 | 支出の区分は「交通費」「交際費」の2種類のみ | 型定義・定数で固定 |
| 2 | サブ区分は区分ごとに固定の選択肢のみ | 定数ファイルで固定値として定義 |
| 3 | 支出一覧は日付降順でソート、同一日付内は登録日時降順 | ExpenseService.list()のソートロジック |
| 4 | テンプレートは手動で並び替え可能、並び順は整数の sort_order で管理 | TemplateService.reorder() |
| 5 | 頻出金額は直近90日・上位5件（固定値） | Settings の fixed 値 |
| 6 | 支出登録時に区分・サブ区分・メモが「前回値」として自動保存される | SettingsService.updateLastUsed() |
| 7 | 前回値は次回の支出追加フォームの初期値として使用される | AddPage の useEffect |
| 8 | テンプレートを並び替える際、全テンプレートのIDが揃っていないと失敗する | TemplateService.reorder()のバリデーション |
| 9 | バックアップインポート時、現在のデータは全削除されてから復元される | ExportService.importJson() |
| 10 | スキーマバージョンが異なるバックアップはインポートできない | ExportService.validateBackup() |
| 11 | 週次比較インサイトは月曜日始まりで計算される（設定値のデフォルト） | AggregationService.getInsights() |
| 12 | タクシー比率は交通費合計に対する割合（交通費が0の場合はnull） | AggregationService.getInsights() |
| 13 | 交際費が多い日TOP3は1日の交際費合計金額で順位付け | AggregationService.getInsights() |
| 14 | 週次比較の変化額は整数に丸める | Math.round() 使用 |
| 15 | サブ区分内訳の割合は小数第2位まで表示 | Math.round((amount/total)*100*100)/100 |

# 10. 確実に言えること（コード・画面から明確に確認できたこと）

1. アプリは4画面構成（追加・一覧・集計・設定）、フッタータブで切り替える
2. データはすべてlocalStorageに保存される。サーバーへの送信は一切ない
3. カテゴリは「交通費（transport）」「交際費（social）」の2種類のみ
4. 各カテゴリのサブ区分は固定値（交通費4種、交際費5種）
5. 支出の金額は1以上の整数のみ受け付ける
6. メモは最大200文字
7. 満足度は1〜5の整数またはnull（未設定）
8. 日付フォーマットはYYYY-MM-DD（正規表現で検証）
9. 支出一覧は日付降順・同日は登録日時降順
10. テンプレートは手動で並び替え可能（↑↓ボタン）
11. 頻出金額は直近90日・上位5件の固定
12. 前回入力した区分・サブ区分・メモが次回入力の初期値になる
13. CSVエクスポートのフィールド: `date, amount, category, subcategory, memo, satisfaction`
14. JSONバックアップはschemaVersion付きで、バージョン不一致時はインポート拒否
15. インポート時は既存データを全削除してから復元（上書き方式）
16. 週次インサイトは月曜日始まりで計算（デフォルト設定）
17. タクシー比率インサイトは交通費全体に対する割合
18. 交際費ピーク日インサイトはTOP3固定
19. PWAとしてホーム画面インストール対応（インストールプロンプト実装あり）
20. Service Workerは5分ごとに更新を確認し、更新があればユーザーに通知する

# 11. 推測を含むこと

1. **ターゲット利用者**: 会社員（交通費・交際費の精算が必要な人）を想定と推測されるが、アプリ内に利用者像の明示はない
2. **金額の最大値**: 実装上の上限制約はないが、localStorageの容量制限（通常5MB）が実質的な上限になり得る
3. **データ量の限界**: localStorageの5MB上限を超えると `QUOTA_EXCEEDED` エラーが発生する実装があるが、実際の上限件数は不明
4. **テンプレートの最大件数**: 上限の実装なし。実質的にlocalStorage容量に依存
5. **メモの上限200文字の根拠**: コードから数値は確認できるが、設定理由は不明
6. **満足度の意味**: UIラベル（「不満」〜「大満足」）から支出行為への満足度と推測できるが、精確な定義はコードに記載なし
7. **「交際費」の定義範囲**: 食事・カフェ・贈答・娯楽・その他のサブ区分から、仕事上の交際費と個人的な交際費の両方を含む可能性がある（区別する機能はない）
8. **CSVの文字コード**: コードから明示的な設定は確認できず、JavaScriptのデフォルト（UTF-8、BOMなし）と推測される
9. **インポート後のデータ検証**: 各Expense・Templateの個別フィールドバリデーションは構造確認のみで、詳細な値チェックの有無は未確認
10. **週の開始曜日の変更機能**: Settings に `week_start` フィールドはあるが、設定画面でユーザーが変更できるUIが存在するか未確認（デフォルト月曜固定の可能性）

# 12. 現行要件のたたき台（As-Is）

## A. アプリ要件

1. 交通費と交際費を日々記録できること
2. 記録項目は「日付・金額・区分・サブ区分・メモ・満足度」とすること
3. 区分は「交通費」「交際費」の2種類のみとすること
4. 交通費のサブ区分は「電車・バス・タクシー・その他交通費」の4種とすること
5. 交際費のサブ区分は「食事・カフェ・贈答・娯楽・その他交際費」の5種とすること
6. 満足度は「1（不満）〜5（大満足）」の5段階またはnull（未設定）とすること
7. 外部サーバーを持たず、端末内にのみデータを保存すること

## B. 支出管理要件

8. 支出を登録・閲覧・編集・削除できること
9. 支出一覧は日付降順で表示すること（同日内は登録日時降順）
10. 支出一覧を月単位・区分でフィルタリングできること
11. 登録時に前回入力した区分・サブ区分・メモを初期値として表示すること
12. 登録済みテンプレートを選択して入力を補完できること
13. 直近90日の頻出金額（上位5件）を候補として表示できること

## C. 集計・分析要件

14. 任意期間の交通費・交際費・合計を集計表示できること
15. サブ区分別の金額と構成比（%）を表示できること
16. 満足度の平均と分布（1〜5段階の件数）を表示できること
17. タクシー比率・交際費が多い日TOP3・週次平均比較をインサイトとして自動提示できること
18. 週次比較は月曜日始まりで計算すること

## D. テンプレート管理要件

19. テンプレートを作成・編集・削除・並び替えできること
20. テンプレートには「名前・区分・サブ区分・金額（任意）・メモ雛形（任意）」を設定できること

## E. データ管理要件

21. 指定期間の支出データをCSV形式でエクスポートできること（列: date, amount, category, subcategory, memo, satisfaction）
22. 全データ（支出・テンプレート・設定）をJSONでバックアップできること
23. JSONバックアップからデータを復元できること（既存データは全削除して上書き）
24. スキーマバージョンが異なるバックアップはインポートを拒否すること
25. 全データを削除できること（確認ダイアログ必須）

## F. バリデーション要件

26. 支出の日付・金額・区分・サブ区分は必須とすること
27. 金額は1以上の整数とすること
28. メモは200文字以内とすること
29. テンプレート名は必須（空白不可）とすること
30. テンプレートの金額を設定する場合は1以上の整数とすること

## G. PWA要件

31. ホーム画面へのインストール（PWA）に対応すること
32. オフライン環境でも追加・一覧・編集・削除・集計が動作すること
33. アプリ更新時にユーザーに通知すること
